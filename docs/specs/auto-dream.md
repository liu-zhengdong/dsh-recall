# Auto Dream：自动复盘

状态：已实现。关联 [issue #1](https://github.com/liu-zhengdong/dsh-recall/issues/1)。

## 目标与边界

让 Agent 定期回顾自己的执行经历，把值得长期记下的内容写进记忆，并留下一份可审阅的审计报告。每次复盘是一条独立、可继续交流的宿主会话，在左侧「任务 / 频道」后的「复盘」页签中显示时间、状态与结果。

**记忆怎么维护不由本插件规定。** 复盘会话挂宿主当前的默认 preset，工具与普通会话一致（含 bash 与读写文件）；记忆放在哪、什么值得收录、写成什么格式，都以它上下文里已有的那份约定为准（通常是用户装的记忆插件注入的）。本插件不自带记忆目录、不规定格式，也不要求安装任何记忆插件；没有那份约定时，复盘只提交审计报告。

原始正文继续保存在宿主日志中。recall 持有复盘进度、批次范围与审计报告，报告每条引用 Run / 消息证据。

## 运行与进度

默认积累 30 条未处理 Run 触发一次，每批最多 30 条；自动尝试间隔至少一小时。按工作目录分别保存进度，全进程同时只运行一次复盘。启动时建立待处理索引，之后由归档事件更新，不在每条归档后重新遍历全部记录。

复盘会话及它派生的会话不进入下一批材料。批次在启动时冻结，失败重试处理同一批材料。普通子 Agent 的经历仍可参与。批次完成、报告落盘且会话正常结束后才推进进度；没有值得记的内容也是明确的完成结果。失败或取消不推进进度。

后台会话通过宿主 agents.create 创建并驱动，不需要保留原会话为活父会话。它读取固定批次的概览，通过 recall_message 针对性回读原始证据，按上下文里的记忆约定维护记忆，并提交报告说明动了什么。每次必须记录检查范围、报告或无新增原因。复盘不加入每步 session/flush 等待链；插件卸载时取消并排空自己的任务。

## 结果与人工纠正

报告保存在 recall 自己的存储域，并可通过工具查询。报告每条保留 Run / 消息证据，明确事实、推断和未验证事项。记忆文件的改动落在插件存储域之外，由复盘会话按记忆约定直接完成；本插件不代理写入、不保存前后对照，也不因失败回滚。

用户可以点入复盘会话查看对话和轨迹，继续对话纠正报告。提供「立即复盘」「停止本次」「暂停 / 恢复自动复盘」「重试」。暂停自动运行不停止当前会话，停止本次不改变自动开关。

## 客户端集成

正式宿主接口提供 sidebar.workspaces 整区槽位、uiWorkspace.openSession 导航与 useSessions / useSessionStatus 订阅。截图中的「任务 / 频道」来自 IM 插件，宿主没有正式的左侧分类页签子槽位。

已有 __dshNativeTabs version 1 注册表时，插入 order 30 的「复盘」，并把复盘会话从普通任务列表排除。纯净宿主提供同一兼容外壳，内部继续渲染原宿主列表。此注册表是插件间的兼容约定，不是宿主正式 API；组件替换和加载顺序必须实测。导航、对话与轨迹沿用宿主，不复制。

列表只传摘要和计数；点「详情」先看到报告与来源，材料范围收在折叠里，原始消息继续按需回读。客户端生成到既有 `./client` 入口，只注册一个宿主模块；复盘视图和回忆设置分别维护源码，共用宿主模块的卸载生命周期。

## 存储与成本

新增独立 dream 存储域，保持 run_archive v1 不变，避免既有归档迁移。工作目录状态与复盘记录各自按记录存储；只更新当前记录。批次最多 30 个定位信息，正文按需回读。报告限制尺寸，列表分页，不把全部历史结果注入提示词。历史复盘按实际会话归档保留，第一版不自动清理用户历史。

## 验证要求

执行已有 check / build 并重建受版本控制的 lib。核对失败和取消不推进、正常无新增推进、复盘与后代排除、重启中断恢复、同一批次重试、simple-memory 缺失和侧栏两种外壳。查看实际 Web 页面与对话 / 轨迹，不以客户端源代码或模型报告代替运行结果。未完成的运行契约核验在交付中明确说明。
