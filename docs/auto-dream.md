# 自动复盘

积累一批未整理 Run 后，dsh-recall 会启动独立后台会话，回顾这批经历、把值得长期记下的写进记忆，并留下一条审计记录。打开左侧「复盘」，查看时间、状态、对话和轨迹。仅安装 dsh-recall 也可使用；审计记录保存在插件自己的存储域中。

## 查看一次复盘

点复盘列表中的标题，进入宿主会话。这里显示 Agent 实际读取的材料、调用的工具和最后的说明。已完成会话可以继续交流；Agent 再次提交报告并正常结束回合后，修正才替换原报告。

点列表项的「详情」，先看到这次提交的审计报告与来源；这次检查的固定材料范围收在下面，展开即可逐条回看原始 Run 和消息。

没有值得记的内容也有明确原因。出现“失败”，表示该批还未完成整理。

## 控制运行

| 操作 | 行为 |
| --- | --- |
| 立即复盘 | 未达到自动门槛时也可运行 |
| 停止本次 | 取消当前后台工作，保留实际过程；自动开关不变 |
| 暂停 | 暂停后续自动启动，当前工作继续；仍可立即复盘 |
| 恢复 | 恢复自动启动，仍遵守门槛和冷却间隔 |
| 重试 | 新建会话，沿用失败、取消或中断复盘的固定批次 |
| 刷新 | 重新读取状态；实时连接断开时重新连接 |

命令与界面使用同一个引擎：

```text
/dream status
/dream run
/dream stop
/dream pause
/dream resume
/dream retry <复盘 ID>
```

`/dream run` 整理全局最早的未整理记录。设为 `autoDream: false` 只关闭自动启动；手动复盘仍可用。

## 复盘做什么

复盘会话拿到固定的一批 Run，然后按四步走：回顾这批经历、判断哪些值得长期记下来、把值得记的写进记忆、提交一份简短的审计报告。

**记忆怎么维护不由本插件规定。** 复盘会话挂宿主当前的默认 preset，拿到的工具与普通会话一致（含 bash 与读写文件）；记忆放在哪、什么值得收录、写成什么格式，都按它上下文里已有的那份记忆约定执行——通常是用户装的记忆插件（如 simple-memory）注入的。没有那份约定时，复盘只提交审计报告，不自己造一个记忆目录。

审计报告是给人快速过目的：每条写清这次动了什么记忆、依据是本批的哪些记录。它不向系统提示词注入，Agent 可用 `dream` 工具回查。

## 自动启动条件与模型

默认全局积累 30 条未整理 Run 后运行，每次最多整理最早的 30 条。同一宿主进程最多运行一次复盘，自动尝试之间至少间隔 1 小时。后台运行最长 10 分钟；进程退出或超时会中断，材料留待下次整理。

复盘只有在提交报告、来源核对通过，并且该回合正常完成后，才推进进度。无值得记的内容但有明确原因也算完成。失败、取消和中断不推进进度。复盘自身及其后代会话不计入新材料。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `autoDream` | `true` | 启用自动启动 |
| `dreamThreshold` | `30` | 全局触发门槛，范围 1–1000 |
| `dreamProvider` / `dreamModel` | 空 | 同时留空使用宿主默认路由；同时填写指定模型 |

`noSummary` 只控制 Run 摘要。它不会关闭自动复盘；若需要停止所有后台模型调用，同时关闭 `autoDream`。

## 数据与边界

复盘结果、整理进度、控制状态和会话归属存于 `dream` 存储域。原始 Run 仍由 `run_archive` 管理，原始消息正文仍由宿主管理。审计报告的每条都引用原始 Run 或消息，并区分事实、推断和未验证信息。

复盘会按记忆约定改动记忆文件，这些改动不在本插件的存储域里，也不会自动回滚。要确认它改了什么，看审计报告和对应复盘会话的轨迹。

删除 Run 不会自动删除已经提交的报告，也不会回滚记忆文件。需要纠正报告时，进入对应复盘会话说明修正；记忆文件按现有编辑方式修改。

左侧扩展使用宿主侧栏槽位。当前“任务 / 频道”来自 IM 插件，复盘会加入同一个页签容器；纯净宿主使用“任务 / 复盘”。IM 的共用页签约定属于插件间约定，未来升级若改变该接口，需要同步适配。

实现职责、失败恢复与接口依据见 [设计](specs/auto-dream.md)。
